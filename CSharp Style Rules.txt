1. Always prefer functional over imperative: NEVER use `for` or `while`.
2. Always prefer explicit over implicit.
3. Methods must always be less than 10 lines.
4. There must never be more than one expression per line.
5. Blocks must not be nested more than two deep.
6. NEVER nest expressions.
8. Use variables or methods to name the results of all complex expressions.
7. All classes, methods, and variables must be named to communicate intentions: NEVER use single letters or abbreviations.
8. Always use nouns to name objects.
9. Always use verbs to name methods.
10. Always use adjectives to name interfaces.
11. Always name booleans like 'isSomething', 'wasSomething', 'hasSomething', etc.
12. Always use the keyword `this`, except to reference static things.
13. Always extract magic numbers and strings to constants.
14. Prefer ternary to if/then, but do not put the condition and both outputs all on the same line (they should take 3 lines).
15. Don't include complicated expressions in ternary operations: extract to variables or methods, as appropriate.
16. Classes must not exceed 100 lines; uses helper classes to separate out concerns and prevent this.
17. NEVER use inner classes.
18. Avoid circular dependencies.

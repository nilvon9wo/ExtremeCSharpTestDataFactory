# Xfty.AutoFixture

Pairs [`Xfty`](https://www.nuget.org/packages/Xfty) with
[AutoFixture](https://github.com/AutoFixture/AutoFixture), in both
directions - core `Xfty` has no dependency on AutoFixture, and never will.

```bash
dotnet add package Xfty.AutoFixture
```

## 1. Point AutoFixture at a RecordProvider

`fixture.Create<T>()` normally knows nothing about XFTY's relationships,
shared ancestors, or cycle guards. `XftyCustomization` intercepts requests
for any type with a Provider registered in your `IProviderLookup` and
answers them with a real, fully-formed XFTY-generated record instead:

```csharp
using AutoFixture;
using Net.NowhereAtAll.Xfty.AutoFixture;

IFixture fixture = new Fixture()
    .Customize(new XftyCustomization(lookup));

Contact contact = fixture.Create<Contact>();
// contact.AccountId is set - the required Account relationship was
// generated by XFTY, not left null.
```

Anything requested that XFTY has no Provider for falls straight through to
AutoFixture's normal generation.

## 2. Let AutoFixture fill in what a Provider left unset

The inverse pairing: generate a record the normal XFTY way, and hand
AutoFixture only the fields nothing touched.

```csharp
using AutoFixture;
using Net.NowhereAtAll.Xfty.AutoFixture;

IFixture fixture = new Fixture();
Account account = (Account)await new RecordProvider(typeof(Account), lookup)
    .SetInsertMode(InsertMode.Mock)
    .SetUnsetFieldFiller(new AutoFixtureUnsetFieldFiller(fixture))
    .Supply();

// account.Name/.Industry/... are exactly what the Provider declared.
// account.NumberOfEmployees, .AnnualRevenue, ... - fields the Master
// Template never mentions - now hold real AutoFixture values instead of null.
```

Nothing stops one fixture from doing both jobs at once.
